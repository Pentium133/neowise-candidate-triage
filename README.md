# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

## Решение

### Запуск и тесты

```sh
node server.mjs   # страница на http://127.0.0.1:3000
npm test          # то же, что node --test; зависимостей нет
```

Тесты поднимают сервер на свободном порту и ходят в него по HTTP через выданный имитатор. `test/api.test.mjs` проверяет некорректный ввод, все пять меток сбоя и лимит 300 мс. `test/view.test.mjs` проверяет, что страница при любом исходе, кроме успеха, получает пустые тему и черновик.

### Что изменено

- `server.mjs` — проверка ввода, лимит ожидания модели, проверка ответа модели. Сервер экспортирует `createTriageServer({ classify, timeoutMs })`, чтобы тест мог подставить свою модель. Порт слушается только при прямом запуске файла.
- `view.mjs` — чистая функция `viewFor(reply)`: ответ API → сообщение, тема и черновик для экрана. Её использует страница и проверяет тест.
- `index.html` — показывает тему и черновик, сообщение о ручном разборе, подсказку при пустом вводе.
- `mock-ai.mjs` не тронут.

### Ответы для описания PR

**Где проверяется результат AI.** В одном месте — `parseModelOutput` в `server.mjs`. Ответ должен быть строкой с JSON-объектом, тема — одна из `delivery`, `pricing`, `other`, черновик — непустая строка. В ответ API уходят только эти два поля, остальное, что вернула модель, отбрасывается. Страница проверяет ответ ещё раз в `viewFor` и не показывает черновик, если статус не `ready`.

**Что происходит при сбое.** Таймаут (300 мс), исключение модели и неподходящий ответ дают HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. По таймауту сервер отменяет запрос к модели через `AbortSignal` и отвечает по таймеру, даже если модель отмену игнорирует. Страница показывает сообщение «Разберите заявку вручную» и стирает тему и черновик прошлой заявки. Так же страница ведёт себя, если сервер недоступен или вернул 500. Прошлый результат стирается уже в момент отправки новой заявки.

**Какой AI использован.** Claude Code: код, тесты и этот текст.

**Что проверено.** `npm test` — 32 теста, все проходят. Сначала тесты были написаны и упали на исходном коде, потом появилась реализация. Запросы `curl` к запущенному серверу: главная страница, `/view.mjs`, успех, пустой ввод, `[timeout]`. Страница в браузере вручную не прокликана.

**Сверх задания.** Тело запроса больше 100 КБ считается некорректным вводом (400). Черновик отдаётся без пробелов по краям.

### Польза для менеджера

Менеджер получает тему и готовый черновик за секунду и не рискует отправить клиенту ответ от прошлой заявки, а измерить это можно медианным временем от открытия заявки до отправки ответа и долей черновиков, отправленных без правок, рядом с долей заявок, ушедших в ручной разбор.
